How Discord permission bitmasks work

Every permission is a single bit, so the bitmask is just the sum of the values of the flags you enable — send_messages (2048) plus embed_links (16384) gives 18432. Two gotchas this tool avoids: first, some flags are above 2^31, and JavaScript's & and | operators coerce to 32-bit signed integers, which silently corrupts the result — so this page uses BigInt end to end. Second, an administrator bit makes every other permission moot, so a decoded bitmask that includes it is worth reading with suspicion. If you are auditing a bot, decode its install URL's permissions value before you accept it.

Frequently asked questions

Why is my bitmask different from another calculator's?

Most often because the other tool did the arithmetic with 32-bit integers. Anything above bit 31 wraps around and you get a plausible-looking but wrong number, which Discord then rejects or, worse, accepts with fewer permissions than you intended. This page keeps every value as a BigInt and only converts to a string at the end.

Do I need applications.commands in the scope?

Only if the bot uses slash commands. If you remove it the install flow still works for a prefix-only bot, but slash commands will not appear in the server's command picker after installing.

Can I change permissions after installing?

Yes, without reinstalling: create or edit a role for the bot and toggle the permission switches, or set channel-level overrides. The role's effective permissions are what the bitmask value would have represented at install time, and channel overrides narrow them further.

Is a high number dangerous?

Not by itself — create_polls is a huge number and grants almost nothing sensitive, while administrator is the value 8 and grants everything. Read the decoded flag names, not the magnitude. A small bitmask with administrator in it is far more dangerous than a large one without it.
